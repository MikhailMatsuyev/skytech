# Skytech — тестовое задание AI-инженера

## О проекте

Тестовое задание для позиции AI-инженера (задание: `docs/task.txt`, заказчик — cherkasov@skytecgames.com).

Суть: сервис, который раз в час обходит Metacritic (раздел Games), забирает 20 новых
необработанных сегодня игр и сохраняет/обновляет их в БД.

**Логика выборки игр:**
- Первый заход — https://www.metacritic.com/game/ , блок New Releases.
- Последующие заходы — https://www.metacritic.com/browse/game/all/all/all-time/new/
  (сортировка "Новые"), постранично — за один заход одна очередная страница.
- Каждый новый календарный день выборка начинается заново (снова с New Releases).

**Данные по игре:** название, обложка, платформы (несколько на игру, напр. ps5/ns2) +
Metascore + Userscore по каждой, разработчик, описание, ссылка на видео, краткое саммари
отзывов критиков и отдельно пользователей (обновляется при повторных обходах).

**Веб-интерфейс (обязательная часть):**
- список игр (краткая инфа), карточка игры (полная инфа)
- фильтр по платформам, поиск по названию, сортировка по рейтингу
- в карточке — похожие игры (среди уже сохранённых), клик по названию открывает их карточку

**Доп. часть 1:** для каждой игры найти самый популярный летсплей на YouTube, транскрибировать
речь блогера, сделать по тексту заключение, прикрепить к игре со ссылкой на ролик.

**Доп. часть 2:** realtime-мониторинг работы сервиса в UI (статусы воркеров, счётчики
обработанных записей) + кнопка принудительного запуска обработки.

**Что нужно сдать:** ссылка на репозиторий, ссылка на развёрнутый сервис, вся переписка с
нейросетью (см. ниже).

## ⚠️ Обязательное требование: вести журнал переписки с ИИ

Задание прямо требует приложить к результату **всю переписку с нейросетью** (можно raw
JSONL). Поэтому весь диалог с Claude по этому проекту нужно фиксировать в
`docs/ai-talks/session-<YYYY-MM-DD>.jsonl` — по одному JSON-объекту на реплику
(`{"turn":N,"role":"user|assistant","text":"..."}`). Реплики `assistant` — предельно кратко
(экономим токены), `user`/`system` можно подробнее, если это суть информации. Полный код/диффы
не вставлять. Начинать новый файл на каждый новый день сессии. Поддерживать в актуальном
состоянии **на протяжении всей работы над проектом**, не только в начале.

## Стек

Монорепо (npm workspaces): `apps/api` (NestJS + TS), `apps/web` (React + Vite + TS),
`packages/shared` (общие типы), `apps/api/prisma` (схема/миграции). БД — PostgreSQL + Prisma.

Сознательно упрощено под тестовое задание: почасовая джоба — обычный `@nestjs/schedule` cron
+ внутренний флаг "уже выполняется" (защита от гонки с ручным запуском) + `EventEmitter2` для
статусов, без очереди. Redis/BullMQ не используются. Для продакшена это очевидная точка
расширения (retries, распределённые воркеры, персистентная очередь, дашборд типа Bull Board) —
для объёма задачи и одного инстанса это избыточно.

**Скрапинг Metacritic**: сайт на Nuxt 3, отдаёт готовый JSON прямо в HTML
(`<script id="__NUXT_DATA__">`, формат сериализации `devalue`) — обычным HTTP-запросом, без
блокировок и без headless-браузера. Парсер (`apps/api/src/scraper`) вытаскивает и разбирает этот
JSON вместо парсинга HTML-вёрстки. Известное ограничение: Userscore по конкретной платформе
доступен только для той платформы, чью страницу открыли (`isLeadPlatform`), у остальных
платформ игры остаётся `null` — можно закрыть отдельными запросами позже.

**LLM-саммари отзывов**: `SummaryService` (`apps/api/src/summary`) — **только локальная Ollama**
(`docker-compose`, модель `qwen2.5:1.5b`), без облачных LLM и без платных API-ключей — осознанное
решение (тестовое задание, не продакшен). Настройки — `OLLAMA_BASE_URL`/`OLLAMA_MODEL` в `.env`.
Если Ollama недоступна — тихо возвращает `null` вместо саммари, обход при этом не падает. Промпт
на английском: язык остального контента с Metacritic и так английский, а модель такого размера
ненадёжно следует инструкции писать по-русски. На публичном дешёвом хостинге (Этап 5) Ollama
может не влезть по ресурсам — тогда придётся либо отключить саммари в проде, либо вернуть облачный
провайдер (сейчас сознательно не делаем).

**Похожие игры**: `GamesService.findSimilarGames` — эвристика (разработчик + пересечение
платформ + близость среднего Metascore), без embeddings/LLM. Проверено на реальных данных.

**Веб-интерфейс**: `apps/web` (React Router) ходит в `GET /api/games`/`GET /api/games/:slug`/
`GET /api/games/meta/platforms` из `apps/api`. `Game.averageMetascore`/`averageUserscore`
денормализованы на upsert для простой SQL-сортировки списка. API — на `/api/*`
(`setGlobalPrefix`), т.к. `/games/:slug` есть и как клиентский роут React Router, и как API-роут —
без префикса они бы конфликтовали при прямом заходе на URL.

**Деплой**: пользователь берёт свой VPS (не Railway/Render, как предполагалось изначально) —
Ubuntu 24.04 без панели управления, доступ по SSH-ключу. Есть `Dockerfile` (multi-stage,
собирает web+api в один образ, отдаёт SPA+API на одном порту) и `docker-compose.prod.yml`
(postgres + ollama + app на порту 80). Прогнано полностью локально — работает. На сам VPS ещё
не выкатывали.

YouTube-часть — не реализована, деплой на сам сервер — в процессе. Актуальный чеклист —
`docs/plan.md`.

## Статус

Готово и проверено: каркас монорепо, Prisma-схема на Postgres, скрапер Metacritic (New Releases +
пагинация SEE ALL + дедуп по дню + upsert в БД), почасовой cron + ручной запуск
`POST /api/scraper/run` с защитой от гонки, LLM-саммари отзывов через локальную Ollama (прогнано
вживую), похожие игры (эвристика, проверено), REST API списка/карточки игр, фронтенд на React
Router — всё собрано в один Docker-образ и прогнано локально через `docker-compose.prod.yml`
(миграции на старте, SPA+API на одном порту, старые данные сохраняются в volume). Дальше —
реальный деплой на VPS пользователя. Подробности — `docs/plan.md`.
